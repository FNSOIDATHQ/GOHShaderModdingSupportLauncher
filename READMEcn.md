## 运行细节

* 启动时，程序将从 %LOCALAPPDATA%\GOHSMSLauncher\settings.conf 加载缓存。
* 无论选择何种启动选项，程序都将遵循以下流程：
0. 将 Environment.CurrentDirectory 移至游戏目录
1. 预处理
2. 使用启动参数启动游戏
3. 隐藏窗口，让程序在后台运行
4. 等待游戏程序结束
5. 游戏结束后，运行后处理
6. 根据设置决定退出程序或重新显示窗口

* 退出时，保存缓存

### 预处理

* 如果没有缓存游戏路径，则运行搜索方法
* * 如果程序位于 steamapps 的子文件夹中，则通过硬编码路径搜索游戏
* * 否则，从注册表中获取 steam 路径，并在所有游戏库中搜索游戏路径
* * 将 Environment.CurrentDirectory 移至游戏目录
* [仅限文件替换方法] 替换游戏根目录中的文件
* * 如果没有找到修改过的 shader.pak，则从程序中提取 pak
* * 否则使用缓存的 pak 替换原始 shader.pak
* 在玩家配置文件中将凹凸贴图质量强制设置为视差

### 后处理

* [仅文件替换方法][需要在设置中启用] 还原原始着色器文件，修改后的文件将保留为缓存
* [需要在设置中启用] 清除 C:\Users\你的用户名\Documents\my games\gates of hell\shader_cache 中的着色器缓存

### 模组预设

模组管理器的预设工具栏可执行以下操作：  
- 将当前加载的列表保存为预设
- 使用当前加载的列表覆盖选中的预设
- 加载已保存的预设
- 重命名预设
- 删除预设

预设是位于启动器可执行文件旁 `presets` 目录中的 UTF-8 TOML 文件。  
在加载预设的过程中，缺失的模组将被跳过，并在警告信息中列出。  
预设文件名即为其显示名称。  

一个预设文件包含：  
- `version = 1`，用于标记预设格式版本
- 一个有序的 `[[mods]]` 数组

```toml
version = 1

[[mods]]
id = “mod_123456”
name = “Workshop 示例”

[[mods]]
id = “local_mod”
name = “本地示例”
```

### Mod 别名

在 **Mod 管理器**中选中一个 Mod，点击**设置别名**即可设置、修改或清除别名。两张表的名称列会加粗显示匹配的别名，悬浮可查看原名。可用 Mod 按显示名称排序，已启用 Mod 保持加载顺序。

**设置 → Mod 别名**可管理全部规则，包括当前未安装的名称。可按原名或别名搜索，选中规则后编辑或删除；点击**添加规则**可填写新的原名和别名。规则按完整原名匹配，区分大小写；不同游戏或来源的同名 Mod 共用规则。Mod 原名变化后需手动修改规则，别名不会再次参与匹配。

规则保存在启动器设置旁的 `%LOCALAPPDATA%\GOHSMSLauncher\mod-aliases.json`，删除 Mod 或清理订阅缓存均会保留。别名仅影响名称显示，不改变 Mod 文件、加载 ID、启用顺序或预设匹配依据。

### Mod 订阅

Mod 管理器的“来源”列会为订阅安装的 Mod 显示 **ModDB、GitHub 或 Mow Portal**。创意工坊项目保留创意工坊来源，没有安装记录的手动项目显示“本地”。关联依据当前游戏的完整安装目录，离线可用，修改别名不影响关联。单选已关联 Mod 后点击“查看订阅”，可打开已保存的项目与文件详情；订阅页的“在 Mod 管理器中查看”会定位对应安装，同一文件有多个安装目录时可先选择目录。平台标签不改变本地着色器缓存操作或文件清理权限。

页面上方中央的 **自动翻译** 工具栏可选择 **Google／腾讯交互翻译（TranSmart）**，翻译当前概览、文章或文件说明。首次默认关闭，目标语言默认跟随界面，之后记住提供者、语言及“原文／译文”选择。旧偏好继续使用 Google，保留原来的开关状态。仅将当前公开正文发送给所选提供者，不发送本地目录、订阅库、日志或验证信息；两者均无需登录或个人密钥。不支持的目标语言会标明不可用并禁用；TranSmart 当前提供英语、简中、日语、韩语、俄语、德语、法语、西班牙语和葡萄牙语，具体源／目标语言组合仍受服务端引擎可用性影响。

正文以有界批次发送，成功片段可在不同页面及部分失败重试时复用；切换提供者会取消旧任务，两者缓存隔离。这些匿名服务为实验性功能，可能不可用或受到限流。短暂故障会有限重试，较长的冷却或不支持的语言组合保留原文，可在右下状态详情查看进度及重试；不会静默将失败正文发送给另一提供者。代码、链接、文件名、版本号、换行、图片位置和下载勾选保持不变，译文不覆盖作者元数据或更新依据。TranSmart 按大陆访问候选服务接入，大陆无代理直连尚未实测。

打开 **Mod订阅**，无需账户即可浏览 ModDB 上的《地狱之门》模组，查看作者概览、文章、图片和文件。收藏与订阅独立保存；订阅前由你选择需要下载的文件，不会自动选中全部文件。

**Mod订阅**位于侧栏 **Mod管理器**之后。在顶部选择来源，输入条件后按回车或点击“刷新”；条件未变时刷新当前页。翻页固定在左下角，状态固定在右下角。“检查订阅”检查当前游戏的全部来源。展开 GitHub 配置即可修改 topics 或添加仓库。

侧栏顶部的菜单按钮可切换名称栏与紧凑图标栏，各图标保留名称提示和键盘导航。收起后可通过语言图标选择中英文。Mod 列表下方、翻页控件左侧的“收起 Mod 列表”可释放阅读空间，“展开 Mod 列表”可从同一位置恢复列表；两项选择都会在重启后保留。窄窗口临时使用紧凑侧栏和列表／详情两步浏览，可通过“返回列表”重新选择；恢复宽度后按手动偏好显示。概览、文章、文件说明及放大图片共用深色阅读背景。

“刷新”统一更新当前列表和阅读内容：描述页更新概览、当前文章及已打开的导航页；文件页更新完整文件列表和当前文件说明。保留阅读位置及仍有效的下载勾选，读取失败时保留旧内容；文件已变更或撤下时清除其旧勾选。连续刷新共用加载中的请求，切换搜索、来源、Mod 或游戏后丢弃过时响应。手动添加的 GitHub 仓库不会因 topics 搜索未包含它而关闭。安装或清理确认期间，请先完成或取消当前确认，再刷新。

点击右下状态可在页内展开进度、缓存提示和失败详情；正文与图片的重试共用统一刷新操作，其他请求成功不会覆盖已有失败。图片在可见时读取并共用加载中的传输。不含查询参数的公开图片会跨重启缓存，未放大的预览图也能复用；十分钟内命中无需图片网络请求，过期后优先使用来源支持的重验证，刷新失败可显示旧缓存并在状态中提示。内存上限 32 MiB，磁盘上限 256 MiB／1,024 个文件。带查询参数的地址只在内存缓存。

**实用工具 → 清除 Mod 订阅缓存**可清理所有来源的正文、图片、译文和阅读历史，并通过弹窗显示实际释放字节数与失败数；返回订阅页时自动重新加载列表与所选内容，保留此前浏览位置。订阅、收藏、已读、偏好、下载包、已安装 Mod、安装任务和独立人工验证会话均保留。

详情分为“描述”和“文件”。描述左侧平级列出概览与每篇文章，导航即读取内容，图片内嵌并可在页内放大和返回。文件页自动读取，左侧竖排列出文件，右侧只显示当前文件说明及下载任务。下载勾选与阅读选择独立，切换文件保留勾选和阅读位置；已选数量和下载操作固定在阅读区下方。安装检查、清理预览及确认均在页内完成。同次浏览复用已成功读取的内容，刷新失败保留缓存。窄窗口通过“返回列表”在列表与详情之间切换。

详情工具区唯一的“打开原文”跟随当前概览、文章、文件、共享版本说明或选中图片，始终使用外部浏览器。图片优先打开已知详情页，否则打开原图。支持的 ModDB、GitHub 与 Mow Portal 链接在软件内打开，翻页控件旁的“返回”恢复上一阅读内容及位置；正文锚点直接滚到对应段落。支持的链接加载失败时保留当前内容，“打开原文”可查看失败目标。其他网页链接仍使用浏览器；点击文件链接不会开始下载。GitHub 发现搜索仍只使用你配置的 topics。

阅读区保留段落、标题、链接、列表、引用、代码、简单表格及正文嵌图的原有顺序。独立图片放在正文上方的横向画廊，可使用滚动条或左右按钮手动浏览，并点击“更多图片”读取下一页，不会自动滚动。正文嵌图保留原位，不在画廊重复显示。旧缓存说明仍可阅读，成功刷新后使用新的有序排版。

单击画廊图片会选中并显示边框，再点击“图片画廊”标题旁的“放大图片”查看所选图。左右方向键及 Home/End 可选择图片，Enter 或空格可放大。图片保持比例并扩大显示，排列更紧凑；翻页、刷新、切换译文及从大图返回均保留选择和滚动位置。生成的图片名称只在放大后显示，仍保留给辅助阅读工具。正文嵌图可直接点击放大，作者独立写下的说明段落保留原位。

在“文件”中勾选需要的文件后，点击“订阅并下载所选文件”即可创建订阅。空间充足时文件列表默认宽 420 像素，可拖动分隔条在 240–480 之间调整，也可聚焦分隔条后使用方向键。文件名单行显示，悬浮可查看完整标题；日期、大小及 Mow Portal 下载来源各自成行，缺失时省略。阅读区较窄时，通过“显示文件列表”和“阅读所选文件”在导航与全宽正文间切换，保留下载勾选和阅读位置。正文保留作者说明及共享版本说明，省去重复的文件标题和元数据。

已订阅时显示“取消订阅”，清理未完成时显示“继续清理”。右下状态详情可查看上次成功检查、更新数量、清理问题及下载可用性诊断。仅有遗留操作时，文件页提供恢复入口；确认前会列出当前游戏的影响范围，涉及继续删除时明确提示。单个失败下载仍使用自己的重试按钮。

切换来源为 **GitHub**，可在配置的 topics 范围内搜索公开仓库。默认 topic 为 `gates-of-hell`；多个 topic 用逗号分隔，选择“任一 topic 匹配”或“全部 topics 匹配”后，点击“保存 topics 并搜索”。关键字和排序始终保留该范围，topics 留空时不执行搜索。“添加仓库 URL”可直接打开 `https://github.com/所有者/仓库` 格式的公开仓库，即使其没有匹配的 topics；同一项目按仓库 ID 去重。

GitHub 描述页展示 README 及其图片，文件页展示公开 Release 附件各自的说明及共享版本说明。没有附件的 Release 仍显示版本说明，不提供下载勾选框。项目类型只是浏览提示，Mod topic 不能证明附件可以安装。工具和需要构建的文件仅供下载后手动使用；没有 Release 的仓库可提供固定到 commit SHA 的源码快照，启动器不会执行构建或生成器。完整标准 Mod 包沿用 ModDB 的归档检查及明确安装确认流程。

切换来源为 **Mow Portal**，可浏览《地狱之门》分类、作者说明、版本说明、图片和公开下载链接。搜索只筛选当前分类页，可点击“下一页”继续查找。Yandex 公开文件支持匿名下载，并沿用标准 Mod 的归档检查和安装确认；其他网盘会展示链接及原网页入口，暂不提供下载。分享关闭、禁止下载或配额耗尽时保留明确失败状态，不引导账户登录。

Mow Portal 的页面或下载链接变化显示“页面或下载链接发生变化，待确认”，不据此认定作者上传了新文件或修改了文件内容。请查看作者页面后自行选择下载；标记已读不会改变已安装版本。

Mow Portal 的作者介绍、图库及通用安装说明保留在概览；共享版本及下载区域说明随当前下载入口显示，不再把介绍重复列为文章或复制到每个文件。缺少单独文件说明时会如实提示。

GitHub 更新检查覆盖全部公开 Release、同一 Release 新增的附件和附件修订。请求使用匿名 API 配额，无需 token 或登录；配额耗尽时显示可重试时间，并保留原文件列表与提示。

“下载与安装”与“描述”“文件”为三个同级选项卡，汇总当前游戏各来源的任务。下载后自动检查放置方案，在明确确认后将内容放入所选游戏的 `mods` 目录。ZIP、RAR、7z、单文件以及包含工具、脚本、DLL、补丁或没有 `mod.info` 的文件均使用同一放置流程；不支持的压缩格式会明确保留为原文件，损坏归档和校验失败仍会报错。启动器不会执行作者程序或修改 `mods` 外的游戏文件；能否通过加载列表启用由 Mod 管理器检查。

首次成功检查文件时建立基线，后续检查提示新增文件及文件修订。已读、忽略状态与实际安装版本分别保存。可以手动检查更新；启动器运行期间也会定期检查订阅。检查失败会保留之前的文件列表与更新提示。

安装预览会提示无法通过游戏 Mod 列表启用的文件夹名称，可在确认前修改；更改作者原目录名可能影响依赖关系。切换界面语言会保留已选布局、目标目录及替换对象，并在确认前重新检查预览。

已下载、失败或已取消的文件任务均提供单独的“取消订阅”入口。确认前会展示将删除的受管安装及下载缓存和将保留的文件；其他已选文件继续保留，移除最后一个文件后也会取消整个 Mod 的更新订阅。Mod 详情中的“取消订阅”可以清理整个 Mod，进行中的下载需先停止。收藏和手动新增文件继续保留。手动修改、归属无法确认的文件，以及 `mods` 外的安装步骤需要单独处理。安装、替换或删除模组前请关闭游戏和编辑器。

ModDB 请求使用 Windows 原生 WinHTTP 后端和 Windows 用户代理设置。正常请求不使用账户凭据或 Cookie。Cloudflare 要求验证时，会暂停对此来源的请求，并提供“打开验证窗口”。请在独立的 Microsoft Edge 或 Google Chrome 窗口中手动完成网站检查，无需登录，然后点击“验证访问并重试”。启动器只有在真实 ModDB 请求成功后才恢复访问；仅打开浏览器或完成一次检查并不保证已经恢复。

验证窗口使用独立的临时浏览器资料。启动器不会读取个人浏览器资料或导入账户 Cookie；只会临时使用该独立会话的 Cloudflare 通行信息和匹配的浏览器身份，并限定在已验证来源。点击“关闭验证会话”即可停止使用此会话。目前内置验证支持 ModDB 网页，其他主机保留原网页与主动重试入口。如果两个浏览器都不可用或验证仍失败，可以继续查看缓存、打开原网页，并在稍后主动重试访问。部分站点验证策略仍可能阻止访问。

其他请求失败时，页面会显示 HTTP 状态码或具体连接错误类别。给 EXE 添加 `--check-moddb` 参数，可以直接测试该 EXE 的联网与解析，不打开界面、不修改订阅或游戏文件。结果与连接详情写入 `%LOCALAPPDATA%\GOHSMSLauncher\Logs\diag.log`（LocalAppData 不可用时使用临时日志目录）；退出码 0 表示已成功读取实时列表。日志不记录带签名的下载地址、验证 Cookie 或凭据。

图片支持在允许的媒体主机之间进行有限次数的 HTTPS 重定向。读取失败会显示 HTTP、内容或解码错误，并可重试；单图限制为 20 MiB，解码前还会检查像素尺寸，防止过大的内存分配。使用 `--check-moddb-images --software-rendering`，可以检查 Replays Unlocked 与 Hotmod 图库，完整下载各自首张缩略图和原图，并由 EXE 自身的渲染器验证解码。此诊断使用同一日志，全部图片检查通过才返回 0；不会打开验证浏览器或修改游戏文件。

### 启动器更新

启动器在打开主窗口后于后台检查官方 GitHub **Latest** 发布版本，成功检查在设置旁的 `launcher-update.json` 中缓存六小时。**关于 → 检查更新**可主动刷新，尚未配置游戏／用户目录时也能使用。请求无需登录或 token，使用 Windows 用户代理设置；GitHub API 配额冷却与 Mod 订阅共享。连接、限流或版本信息错误会保留上次成功记录。

只有严格高于当前版本的数字版本才提供更新，支持可选的 `v` 前缀及二至四段数字，例如 `v4.00`、`v4.00.1`。相同版本或较旧发布不会替换当前启动器。预览版、旧 WPF 附件或不支持的版本格式可通过“打开 GitHub 发布页”查看。自动下载要求发布中存在唯一的 `GOHShaderModdingSupportLauncher.exe`，且 GitHub 提供有效的 `sha256` 摘要。发布时应上传 `Publish-Aot.ps1` 生成的最终 Windows x64 单文件 EXE，包含追加的原生库包；脚本会在打包完成后输出整个 EXE 的 SHA-256。

点击“下载并更新”后可查看进度或取消。文件大小、SHA-256 及 x64 可执行文件头校验通过后才准备替换。启动器保存设置并经过正常的订阅退出清理，由独立助手再次核对新旧文件后原子替换，将旧版保留为 `old.exe` 并重启。目录中已有 `old.exe` 时会停止更新，请先移走或删除该备份。替换或创建新版进程失败时尝试恢复旧版，错误写入启动器旁的 `.update-error.log`。若新版已启动但随后出现运行问题，可使用保留的 `old.exe` 手动恢复。

使用 `--check-launcher-update` 可验证当前 EXE 自身的匿名版本信息请求，不下载或应用附件。退出码 0 表示请求与解析成功，当前发布标签、是否可更新及不兼容原因写入诊断日志。原工坊更新器及界面流程保存在 [Legacy/WorkshopUpdater](Legacy/WorkshopUpdater/README.md)，已从正式构建中排除。

### 注意事项
* 强制改变凹凸贴图质量是一项特殊措施，用于支持我的着色器mod
* 将 Environment.CurrentDirectory 移至游戏目录总是必要的，这样steam就不会截断我们的启动指令
* 设置保存在用户 LocalAppData 目录，首次使用会兼容读取 EXE 旁的旧 settings.conf。
* 启动游戏时可选附带-showmodinfo参数，这是我发现的增强指令，可以显示详细的mod信息
* 启动器更新会保留 `old.exe`，确认新版正常后请在下次更新前移走或删除该备份。

使用 `--check-google-translation` 或 `--check-transmart-translation` 可检查 EXE 自身的匿名 WinHTTP 翻译，覆盖公开短句、超过 3,000 字符的多段长文、英译简中和简中译英、受保护内容、换行、缓存与取消；俄译简中样本遇到引擎不可用时单独记录。检查不打开界面或修改游戏文件；短句／长文、两个目标和缓存／取消等必需检查通过时退出码为 0，结果及俄语引擎情况写入同一诊断日志。诊断使用 Windows 用户代理设置，不能作为大陆无代理证据。翻译偏好单独存入 `translation-settings.json`，有容量限制的译文缓存仅保存在内存，实用工具中的订阅缓存清理会同时清理所有提供者。

Mod 目录检查在后台进行，先显示发现的目录，再逐项更新结果；尚在检查的 Mod 仅显示“检查中”，不阻塞导航、停用或排序。两张表使用“来源”和可调整宽度的“特征”列；悬停在列名旁的信息符号，可查看四行说明，其中的徽标与列表样式相同。已确认的普通内容显示“常规”；可执行文件、着色器和其它为独立特征，四种标签可以同时出现。“其它”表示附加或未分类内容，也用于尚未确认正常加载结构的目录。可选压缩附件无法检查或局部检查未完成，不会撤销已确认的常规标签。资源与本地化子目录中的 PAK、正常 PAT 补丁按游戏包检查；说明文档和已确认的文本备份不会仅因存在就追加其它。别名、来源和已启用顺序保留。

mod.info 检查只识别 Mod 声明及其直属名称，允许在 Mod 块之前、之后或内部出现其他声明块，包括 delete 等游戏指令。启动器只将这些块作为数据跳过，不解释或执行指令，也不校验游戏版本、依赖和各指令的业务参数。识别时会区分注释与引号内文本；未闭合结构或有歧义的 Mod 名称仍不能确认为可用描述。

激活会检查根描述可用、已确认普通内容以及加载 ID 有效且无冲突；“其它”、可执行文件特征和可选范围检查未完成本身不会阻止激活。加载 ID 无效或重复时，保留已确认的常规标签，单独拒绝激活。被拒绝项提示“该mod无法通过激活使用”，含“可执行文件”标签时另起一行提示“DLL注入mod请根据作者说明手动安装”。混合 Mod 可以激活普通内容，激活不会执行脚本或部署 DLL。加载预设会在后台重新检查；遇到不符合条件的项整批拒绝，保持当前启用列表和原预设文件，缺失项仍单独提示。既有启用列表中的异常或缺失项保持可见，检查期间也能停用、排序。启动游戏／编辑器以及退出后的锁定列表恢复使用同一资格检查，先于着色器处理或启用列表写入。退出恢复会保留扫描期间新修改的启用列表和外部 options 编辑；取消扫描或切换游戏后，旧结果不会恢复旧列表。普通刷新不改启用列表；停用普通内容不会卸载另行安装的 DLL。订阅文件仅使用当前游戏明确关联的本地安装结果；本地检查进行中显示“检查中”，尚未安装或扫描的远程项保持“尚未检查”。

## 开发指南

我使用 Visual Studio 2026 构建这个程序，环境配置如下:
* 仅支持 Windows x64；构建 AOT 需要 .NET 10 SDK 和 Visual Studio C++ 构建工具。Release 构建固定使用 10.0.15 版 .NET 运行时和 Native AOT 编译器，不依赖 SDK 自带的补丁版本。
* Avalonia Desktop 与 Fluent Theme 12.1.3、DataGrid 12.1.2
* 执行 `powershell -NoProfile -ExecutionPolicy Bypass -File .\Publish-Aot.ps1`，只分发 `bin/net10-aot-single-file/` 中的 EXE。
* EXE 已包含 .NET 运行时和原生 UI 库，目标电脑无需安装 .NET。
* 首次启动会校验原生 DLL 并释放到 `%LOCALAPPDATA%\GOHSMSLauncher\Native\<压缩包 SHA-256>`；必要时使用 `%TEMP%`。缺失或损坏的文件会在下次启动时恢复。
* 使用 `--software-rendering` 启用软件渲染；`--validate-native-bundle` 可以在不打开界面的情况下校验封装；`--self-test-ui` 检查七页、稳定导航、中英文与模组操作，不联网，也不会启动游戏。
* DataGrid 12.1.2 的反射功能会产生两条上游 AOT 分析摘要。本项目仅使用固定只读列和编译绑定；发布脚本会拒绝其他裁剪或 AOT 警告。Release 还原会审计直接和间接依赖，发现已知漏洞告警时阻止分发。
* `Properties/i18n.Designer.cs` 保留了内嵌中文资源查找逻辑；新增资源键时需同步维护该文件。
* 从提交a120cb0开始本项目使用Codex辅助开发
